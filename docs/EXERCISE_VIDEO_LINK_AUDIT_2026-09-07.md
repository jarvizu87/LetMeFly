# LetMeFly Exercise Video Link Audit — 2026-09-07

## Scope

This audit covers the exercise-video records embedded in the current LetMeFly Command V2 production build after the complete Crownforge overlays are applied.

Current embedded production library reviewed: **92 canonical exercise records**.

## Baseline findings

Immediately before the full video hardening pass:

- **27** records were marked `direct-source-library`.
- **1** of those 27 was the newly replaced Front Squat YouTube direct video.
- The other **26** direct records still pointed at legacy Vimeo pages, representing **21 unique Vimeo URLs**.
- **65** records already used YouTube search-result URLs: **38** `plan-linked-search` and **27** `search-fallback`.
- Front Squat's original Vimeo page was directly confirmed unavailable during the Galaxy release test.
- The remaining legacy Vimeo pages were not treated as approved merely because their URLs existed. They belonged to the same old direct-link catalog and could not be guaranteed available to an athlete on workout day.
- Several legacy Vimeo URLs were reused across materially different exercise variants:
  - Clean-Grip RDL to Knee / Romanian Deadlift
  - Glute Bridge / Glute Bridge Isometric Hold
  - Lat Pulldown / Neutral-Grip Lat Pulldown / Wide-Grip Lat Pulldown
  - Push-Up / Scapular Push-Up
- Several YouTube-search links contained stale or ambiguous wording such as alternative exercises, provider prefixes, or literal `YouTube Search` text. Those URLs were reachable but could return the wrong movement first.

## Release remediation

For the Monday release, LetMeFly now applies these rules during every production build:

1. The Front Squat legacy Vimeo URL is replaced by the currently approved direct YouTube demonstration.
2. Every other legacy Vimeo `direct-source-library` record is **demoted to an honest YouTube search fallback** until a replacement direct instructional video is manually reviewed and approved.
3. Every search fallback is normalized to the **exact canonical exercise name + `exercise tutorial`**. Alternate movement names are not mixed into one query.
4. A build-time audit rejects:
   - any remaining Vimeo URL in the embedded exercise library,
   - a `direct-source-library` record that is not a direct YouTube video,
   - a search-status record that is not a YouTube search-results URL,
   - stale `YouTube Search` or `+or+` query wording.

## Verified production state

After remediation, the compiled production library contains:

- **92 total exercise-video records**
- **1** approved direct YouTube record
- **38** `plan-linked-search` records
- **53** `search-fallback` records
- **0** Vimeo URLs in the embedded exercise library
- **91** exact-name YouTube search-result fallbacks

The production artifact generated by the video-audit build was independently inspected after CI: the compiled exercise library contained **zero `vimeo.com/` references**, one Front Squat direct YouTube URL, and the expected exact-name search fallbacks.

## Policy

The release policy is intentionally conservative: **a clearly labeled search fallback is preferable to a broken or misleading direct video**.

A record will only be promoted back to `direct-source-library` after the actual instructional video and movement match have been reviewed. This keeps the app honest about what is vetted and prevents an old URL from masquerading as an approved demonstration.

This video-link work changes exercise intelligence only. It does **not** modify Crownforge prescriptions, loads, sets, reps, exercise selection, or progression logic.

## Follow-up

The long-term target remains a fully vetted direct-video library for every programmed exercise, using reputable instructional sources and editable links. The current search-fallback layer is the safe production bridge while that direct-source curation continues.
