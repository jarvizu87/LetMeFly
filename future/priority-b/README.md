The next Coach batch reads saved goals, training background, preferences, equipment and coaching notes from the active athlete profile. It makes missing context explicit and links to the existing profile editor. Cleared fields remain blank, legacy fields provide compatible fallbacks, and profile text is rendered literally. The browser audit covers native profile save, Coach reload and unchanged source/outbox snapshots during read-only views. This does not seed or fill a real athlete profile.

Profile import and persistence: a profile-only JSON file is bound to the active athlete and can stage selected details in the existing editor. Blank fields are selected by default; existing values require selection before replacement. Preview and form staging never persist. Saving uses a single native transaction for the athlete row and sync outbox, rejects stale edits, preserves unrelated context and treats repeat saves as no-ops. Private imports are never bundled or committed. `ci/audit-profile-context.mjs` covers validation/merge boundaries; `ci/audit-profile-context-browser.mjs` exercises the real editor, queue, concurrency, rollback and Coach reload with disposable athletes.

The advanced Progress batch adds completion against saved session prescription slots, distributions using unique catalog role/primary-muscle identities, top logged loads at the same rep count, and explicitly linked historical readiness ratings. Group counts overlap; unknown identities are unmapped. Missing or inconsistent saved plans are excluded from completion percentages, extras are separate, and calendar attendance is never inferred. Distance/time sets cannot create load trends. All views remain read-only and follow the active date/exercise filters. `ci/audit-progress-detail.mjs` covers the calculation boundaries; the existing browser audit now covers these views, filter behavior and preserved source/outbox records.

The current-feedback Coach batch adds an explicit, in-memory check-in and routes the reported situations through the unchanged 14-rule v1.9R5 decision manifest. It shows source priority, original DR IDs, STANDBY status, supporting report fields, history/effort sample counts and missing context. The first applicable source situation is reviewed before the others; multiple rules do not become a combined adjustment plan. Specialty guidance requires an explicit primary-stability assessment, and conflicting assessments withhold that routing. Declining loads never infer a primary-performance decline. Profile text and historical readiness never supply current pain, equipment, technical-quality or interference answers.

Each check-in is bound to the active athlete, unique active program instance/position, ongoing session identity and selected exercise. A changed answer invalidates its prior review. Reviews expire after 15 minutes, clear on route exit/reload, and require confirmation again after a context change. This freshness limit is a UI rule, not a recovery threshold. Native Train links point to the existing workout and Substitute Today controls; the Coach check-in cannot write any store or apply a prescription, substitution, training max or program change.

`ci/audit-coach-decisions.mjs` covers source qualification, explicit triggers, identity, staleness, priority, conflicting feedback and evidence counts. `ci/audit-coach-decisions-browser.mjs` covers native mobile/desktop behavior, expiry, context invalidation, safe navigation, focus/layout and complete private-store/web-storage immutability. It defaults to loopback port4173; `LMF_AUDIT_BASE_URL` permits an isolated loopback QA port.

Source boundary still open: no additional Training Intelligence ranking/scoring dimensions are imported in this batch. Those original rows and their candidate scopes require source review before integration. The provenance-bearing decision index supplies review context only and does not promote its standby rules to authorized changes.
